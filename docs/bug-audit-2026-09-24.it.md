# Audit di stabilità — 24 settembre 2026

Round locale successivo alle correzioni di riproduzione, selezione del profilo della
sorgente ed esportazione dei media. Nessuna pubblicazione richiesta in questo round.

## Riproduzione e trasporto

- La ripresa HTTP ora gestisce anche gli endpoint senza parametri `range`, i server
  che ignorano `Range`, gli intervalli `Content-Range` incoerenti, l'EOF esatto e
  la chiusura di una lettura bloccata. I tentativi rimangono limitati.
- Una risoluzione tardiva del motore alternativo non può sostituire un video dopo
  il passaggio a un altro elemento della coda. Le risoluzioni per metadati o
  download non sovrascrivono più la configurazione di recupero della riproduzione.
- Normalizzati velocità non finite e offset di seek fuori scala, inclusi i
  percorsi Cast. Eliminati i duplicati all'interno di un'aggiunta alla coda.
- Le sorgenti vengono costruite prima di modificare coda e qualità selezionata.
  Un manifest non valido lascia intatta la sessione precedente; la UI segnala il
  fallimento del cambio qualità senza propagare l'eccezione al thread principale.
- Nel controllo di avvio è stato trovato un vecchio elemento con URL `lbry://`
  etichettato come YouTube. Il resolver corregge il provider anche per elementi
  già salvati, preservando ID e playlist; le importazioni nuove non assegnano più
  YouTube agli URL sconosciuti. I domini sono riconosciuti per host, non per
  sottostringhe. Aggiunte quattro regressioni per questo caso.

## Account e isolamento dei profili

- Il logout elimina anche la vecchia chiave di autenticazione del profilo
  principale; un user agent JSON nullo non diventa più la stringa `null`.
- Il login WebView riparte dalla sessione del profilo scelto, non dai cookie
  lasciati da un altro profilo. Le credenziali salvate degli altri profili restano.
- I callback concorrenti producono snapshot indipendenti; callback di una WebView
  distrutta e inizializzazioni V8 obsolete non possono ripristinare vecchi account.
- Risoluzioni e storyboard usano il profilo catturato all'inizio della richiesta.
- Configurazione del login: lettura limitata a 2 MiB, timeout di rete e parsing
  fuori dal thread UI; persistenza credenziali asincrona con gestione degli errori.

## Esportazioni, libreria e importazioni

- Il convertitore viene fermato prima di eliminare i file temporanei o riutilizzare
  l'encoder. Le esportazioni concorrenti sono serializzate per elemento.
- Errori nei callback di progresso vengono riportati al job, non al main looper.
  Monitoraggio spazio durante la conversione, progresso finito e monotono, nomi
  file compatibili con i limiti UTF-8 senza spezzare caratteri Unicode.
- Le istanze della libreria e le preferenze delle iscrizioni condividono un blocco
  per profilo. Un rollback non può cancellare cronologia/iscrizioni salvate da
  un'altra istanza mentre un'importazione sta terminando.
- Ogni modifica agli overlay del progresso invalida le cache delle altre istanze.
- Un registro di recupero non ripristinabile viene conservato in quarantena prima
  di consentire nuove modifiche; un marker durevole evita rollback tardivi dopo
  un'interruzione della quarantena. Se nemmeno la conservazione è possibile,
  le scritture vengono bloccate; lettura e avvio restano disponibili.
- Il prerequisito asincrono condiviso dei download restituisce il proprio errore
  ai singoli job: un fallimento di salvataggio non annulla più il padre senza
  gestione, causando un'eccezione globale. La cancellazione rimane cancellazione.

## Verifiche

Le suite nuove coprono server HTTP locali difettosi, sostituzione atomica delle
sorgenti, callback di login concorrenti, rollback e quarantena interrotti,
scritture concorrenti, errore/cancellazione dei prerequisiti e spazio esaurito.

Aggiunti 45.000 casi generativi deterministici: 10.000 recuperi playback,
20.000 velocità/seek, 10.000 invalidazioni sessione e 5.000 nomi Unicode.
Sono test generativi mirati, non fuzzing coverage-guided dell'intera applicazione.

- 304 test JVM dell'app e 35 del backend passati.
- 40 test strumentati passati sul Pixel 9a, esclusivamente in grayTEST: trasporto
  HTTP (8), atomicità sorgenti (1), concorrenza libreria (2), recupero sicuro (5),
  autenticazione (3), transazioni import (3), cache tra repository (1), backup (4),
  proprietà notifiche (2), job (4), playlist (4), target player (1), morph (1),
  proxy Cast locale (1).
- Hash della libreria principale e delle preferenze identici prima/dopo la suite.
- Nessun nuovo crash osservato nel buffer dei crash del dispositivo dopo le prove.
  Due vecchi download hanno restituito errori di contenuto non disponibile dalla
  sorgente: sono stati gestiti come fallimenti del job, non come crash dell'app.
- Build debug e release, incluso il controllo lint vitale della release, passate.
  Il controllo lint completo delle traduzioni non è stato rieseguito in questo round.
- Ultimo APK ARM64 installato sul Pixel con package dedicato e nome launcher
  grayTEST; suite dei 40 test ripetuta con esito positivo sull'APK finale.
  Avvio della schermata Home verificato. Nessun commit, push o tag creato.

## Limiti

Le verifiche automatiche non equivalgono a una garanzia di assenza di ogni bug.
Login con account personali, ricevitori Cast fisici e dispositivi Android non
collegati non sono stati esercitati. I test dati usano profili sintetici; l'app
Grayjoy di produzione e il secondo telefono non vengono modificati.
